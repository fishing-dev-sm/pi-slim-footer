> Скриншоты рендерятся полностью программно (`scripts/screenshots.sh`: настоящий `src/index.ts` выдаёт ANSI-строки → PIL рисует PNG ячейка за ячейкой) — без артефактов реального скриншота терминала.

Однострочное расширение футера для [pi](https://pi.dev) — строго одна строка, бейджи в true color, умное отбрасывание сегментов на узких терминалах. Замена statusline-pi.

## Предпросмотр

```
 AUTO   deepseek/deepseek-v4-pro high   CTX ⣀⣀⣀⣀⣀⣀⣀⣀ 0.0%·1M   ⎇ main   -- tps   $0.026        ~/code/pi-fleet
```

Широкий терминал (тема badges, инвертированные бейджи в true color): режим / модель + уровень размышления / CTX (braille + % + окно) / git / tps / стоимость; каталог выровнен вправо.

## Возможности

- **Главная строка строго одна**: наш контент владеет строкой 0 и не переносится ни при какой ширине; не поместившиеся сегменты отбрасываются по приоритету
- **Управление строками плагинов**: содержимое `setStatus` других плагинов должно располагаться на отдельных строках (по умолчанию `-1`, сразу под главной строкой). `/slim-footer` назначает номера строк по числовой оси (**положительные = выше главной строки, отрицательные = ниже**); **одинаковый номер = общая строка** (через пробел), разные номера = отдельные строки. Меню предлагает ±1..±9 (18 слотов); в конфиге можно вручную указать любое целое в ±99
- **Порядок отбрасывания** (больший номер отбрасывается первым): `cost(5) → tps(4) → git(3) → CTX(2) → model(1) → режим разрешений (0, не отбрасывается никогда)`
- **Режим разрешений как полноценный гражданин**: `yolo` от permission-system рисуется жёлтым бейджем ` AUTO ` (больше не голая вторая строка текста); зарезервированы `plan` → ` PLAN ` и `ask` → ` ASK WHEN NEED `; остальные статусы расширений получают серый бейдж
- **Две темы**, переключаются через `/slim-footer`:
  - `badges` (A): все бейджи инвертированные, стиль FACC
  - `mixed` (B): цветные бейджи состояний + приглушённый текст данных, низкая насыщенность
- **Эмоциональные цвета**: CTX зелёный → жёлтый → оранжевый → красный → тёмно-красный (5 уровней); tps окрашен по скорости (<10 синий / <30 бирюзовый / <60 зелёный / ≥60 оранжевый)
- **Малонасыщенная палитра**: HSL-десатурация (настраивается) — не утомляет глаза при долгой работе

## Установка

Добавьте `npm:pi-slim-footer` (или локальный путь) в `packages` в `~/.pi/agent/settings.json` и удалите `npm:statusline-pi` (оба захватывают футер):

```json
{
  "packages": ["npm:pi-slim-footer", "...другие пакеты..."]
}
```

## Конфигурация

`~/.pi/agent/slim-footer.json` (всё необязательно, см. [config.example.json](config.example.json)):

```json
{
  "enabled": true,
  "theme": "badges",
  "saturation": { "badgeSat": 0.3, "badgeLum": 0.72, "foreSat": 0.4 },
  "pluginLines": { "swarm-roster": 1, "noisy-ext": -2 }
}
```

## Команда

`/slim-footer` — меню:

1. Переключение темы badges / mixed
2. **Plugin line positions…** — показывает все плагины, зарегистрировавшие статус футера (с предпросмотром текущего статуса), и назначает каждому номер строки (координату на числовой оси):
   ```
   Line +9 … +2 / +1   → выше главной строки (+1 — ближе всего)
   Line  0             → главная строка slim-footer (плагинам недоступна)
   Line -1 / -2 … -9   → ниже главной строки (-1 — ближе всего, по умолчанию -1)
   ```
   Плагины с одинаковым номером делят строку через пробел; номера сохраняются в `pluginLines` (файл принимает ±99).

   > Начиная с v0.3.0 ось использует семантику числовой прямой (положительные = вверх). Старые конфиги (положительные = вниз) автоматически инвертируются при первой загрузке и перезаписываются с флагом `axisMigrated`.

   Правило рендеринга статусов плагинов: **текст, уже содержащий ANSI-стили, передаётся как есть** (например, бирюзовый бейдж `MANAGER` из pi-agent-swarm); простой текст оборачивается в наш серый бейдж.
3. Включить / выключить (при выключении восстанавливается стандартный футер pi)

## Источники данных

| Сегмент | Источник |
|---|---|
| Бейдж режима | Записи `footerData.getExtensionStatuses()`, значение которых — известный режим (yolo/plan/ask) |
| Строки плагинов | Остальные записи `footerData.getExtensionStatuses()`, распределённые по `pluginLines` |
| Модель / уровень размышления | `ctx.model` + `pi.getThinkingLevel()` |
| CTX | `ctx.model.contextWindow` + `ctx.getContextUsage().tokens` |
| git | `footerData.getGitBranch()` (встроено в pi, git не запускается) |
| tps | Оценка по событиям `message_start/update/end` (заимствовано у statusline-pi) |
| стоимость | Сумма `usage.cost.total` по assistant-сообщениям ветки сессии |
